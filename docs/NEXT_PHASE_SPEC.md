# 토타시 영어 다음 단계 개발 명세서

- 대상 버전: 0.7.0 → 0.8.0 ~ 1.0.0
- 작성일: 2026-11-04
- 읽는 사람: 이 앱을 이어서 개발하는 Claude
- 사용자: 안드로이드 휴대폰과 태블릿을 함께 쓰는 1인 학습자, 코드는 직접 작성하지 않음

## 1. 이번 단계의 목표

학습자가 **레벨에 맞는 표현과 단어를 공부하고, 승급 심사를 통과해 레벨을 올리며, 두 기기에서 같은 기록을 이어 가게** 만든다.

| 번호 | 기능 | 핵심 |
|---|---|---|
| 1 | 레벨 시스템 | NL~AL 9단계, IL에서 시작 |
| 2 | 단어 학습 | 레벨별 단어, 자동 복습 |
| 3 | 승급 심사 | 진도를 채우면 응시 가능, 합격해야 승급 |
| 4 | 내 문장 예시 | 표현마다 한국어 예시 약 20개, 무작위 3개 표시 |
| 5 | 동기화 | Google 로그인, 기기 간 기록 병합 |

### 이번 단계에서 하지 않는 것

- AI 역할극
- 발음 진단
- 리그전, 다른 사용자와의 경쟁
- 옷장과 학습 보상
- 네이티브 앱 전환, 앱스토어 등록

## 2. 반드시 지킬 원칙

아래는 사용자가 직접 요청했거나 이미 확정한 사항이다. 임의로 바꾸지 않는다.

### 조작

- 뒤로, 다음, 홈, 탭 등 **이동 버튼은 모두 화면 아래쪽**에 둔다. 화면 위쪽에는 조작 버튼을 두지 않는다.
- 학습 중 조작 버튼은 `.dock`, 그 외 화면은 하단 탭 `#tabs`를 쓴다.
- 안드로이드 뒤로 가기 버튼과 제스처는 앱 안의 뒤로 가기와 같게 동작한다.
- 새 화면은 모두 `setScreen(name, render)`으로 등록하고, `vcDo('back')`에 뒤로 갈 곳을 추가한다.

### 음성

- 평소에는 **한국어**로 듣고, 영어로 답하는 화면에서만 **영어**로 듣는다.
- 언어 결정은 `VOICE.langOf(screen)` 한 곳에서만 한다.
- 새 기능의 음성 명령은 `voice.js`의 `COMMANDS`에 추가한다. 명령어 사전은 여기서 자동 생성된다.
- 음성으로 할 수 있는 일은 터치로도, 터치로 할 수 있는 일은 음성으로도 가능해야 한다.

### 디자인

- 리퀴드 글래스 스타일을 유지한다. 반투명 유리 카드, 광택 버튼, 입체 아이콘을 쓴다.
- 새 색을 직접 쓰지 말고 `style.css`의 `:root` 변수를 쓴다. 라이트와 다크 모드 모두 확인한다.
- 입체 아이콘은 `i3d(name, color)`를 쓰고, 새 모양은 `SHAPE`에 추가한다.
- 이모지를 아이콘 대신 쓰지 않는다.
- 카드마다 그림자, 테두리를 새로 정의하지 말고 기존 유리 재질 규칙에 선택자를 추가한다.
- 휴대폰 390px, 태블릿 1180px 모두에서 가로 스크롤이 없어야 한다.

### 토타시

- 재잘거리는 어린 막내 여동생 말투, 반말, 이모지 없음.
- 사용자를 `{호칭}`(언니 또는 오빠)으로 부른다.
- 원본 파츠 `assets/toto/layers`만 사용하고, 캐릭터를 새로 그리지 않는다.
- 상황별 표정은 `FACE`에 추가한다. 승급 합격은 `done`, 불합격은 `wrong` 표정과 위로 대사를 쓴다.

### 비용과 오프라인

- AI 없이도 퀴즈, 복습, 단어, 승급 심사가 오프라인에서 동작해야 한다.
- 앱 실행 중 AI 호출은 사용자가 직접 요청한 교정에만 쓴다. 월 한도 `S.aiLimit`(기본 1달러)을 지킨다.
- API 키는 동기화하거나 백업하지 않는다.

### 콘텐츠

- 말해보카 등 다른 서비스의 문제와 단어 목록을 복제하지 않는다. 모든 콘텐츠는 직접 작성한다.
- 영어는 자연스러운 일상 표현이어야 하고, 한국어 뜻은 번역투를 피한다.

## 3. 현재 코드 구조

빌드 도구 없는 정적 PWA이며 GitHub Pages로 배포한다.

| 파일 | 역할 |
|---|---|
| `index.html` | 뼈대, 아이콘 그라데이션, 탭 |
| `style.css` | 디자인 전체 |
| `srs.js` | 복습 일정, 채점, 세션 구성(화면과 분리된 순수 함수) |
| `voice.js` | 음성 명령과 해석(화면과 분리된 순수 함수) |
| `app.js` | 화면, 상태, 음성 제어, AI 호출 |
| `sw.js` | 오프라인 캐시, `FILES` 목록 |
| `data/expressions.json` | 표현 300개 |
| `tests/` | `node tests/srs.test.js`, `node tests/voice.test.js` |

주요 지점:

- 상태: `S`(localStorage `totasi-english-v1`), 기본값 `FRESH_STATE()`
- 표현 항목: `{id, topic, level, expression, meaning, en, ko, blank, note}`
- 학습 기록: `S.cards[id] = {reps, lapses, due, days, seen}`
- 세션 구성: `SRS.buildSession(items, cards, mode, now)`
- 복습 단계: `SRS.stageOf(card)` → `blank`, `arrange`, `sentence`
- 문제 화면: `quiz(e)`, `drawAns(e)`, `answer()`, `showResult()`
- 자유 연습: `startPractice(stage, title)`, 복습 일정에 영향 없음
- 학습 메뉴: `STUDY_MENU`에 한 줄 추가
- `.dock`은 `panel()`이 `#dockSlot`으로 옮긴다. 유리 효과 안쪽에 두면 화면 하단에 고정되지 않기 때문이다.

### 배포 규칙

1. `app.js`의 `APP_VERSION`과 `sw.js`의 `CACHE`를 함께 올린다. 테스트가 일치 여부를 검사한다.
2. 새 파일은 `sw.js`의 `FILES`에 추가한다.
3. 모든 경로는 상대 경로로 쓴다. 사이트 주소에 `/totasi-english/`가 붙는다.

| 단계 | 버전 | 내용 | 사용자 작업 |
|---|---|---|---|

| B | 0.9.0 | 단어 학습 | 없음 |

## 5. 레벨 시스템

### 레벨 정의

```js
const LEVELS = ['NL','NM','NH','IL','IM1','IM2','IM3','IH','AL'];
```

| 레벨 | 화면 설명 | 표현 | 단어 |
|---|---|---|---|
| NL | 단어로 말해요 | 신규 20 | 100 |
| NM | 외운 문장으로 말해요 | 신규 20 | 100 |
| NH | 짧은 문장으로 말해요 | 신규 30 | 120 |
| IL | 쉬운 문장으로 답해요 | 기존 난이도 1의 60 | 150 |
| IM1 | 일상 대화를 시작해요 | 기존 난이도 1의 37 + 난이도 2의 30 | 150 |
| IM2 | 대화를 이어 가요 | 기존 난이도 2의 60 | 150 |
| IM3 | 경험을 설명해요 | 기존 난이도 2의 51 | 150 |
| IH | 의견과 이유를 말해요 | 기존 난이도 3의 62 | 150 |
| AL | 복잡한 상황을 풀어 가요 | 신규 40 | 120 |

표의 분량은 첫 배포 기준이며, 항목 수는 코드에 고정하지 않고 데이터에서 계산한다.

주의:

- OPIc의 등급 이름을 참고한 **앱 자체 연습 지표**다. 레벨 화면에 "실제 OPIc 등급과 다를 수 있어요"를 표시한다. 등급을 보장하는 문구를 쓰지 않는다.
- 사용자는 IL에서 시작한다. NL~NH는 잠기지 않으며 기초 복습용으로 고를 수 있다.
- 레벨은 내려가지 않는다.

### 데이터 변경

표현에 `opic` 필드를 추가하고, 기존 `level`은 유지한다.

```json
{ "id": "trv-01", "topic": "travel", "level": 1, "opic": "IL" }
```

- 네 주제가 레벨마다 고르게 섞이도록 배정한다.
- 기존 표현의 `id`는 절대 바꾸지 않는다. 학습 기록의 키이기 때문이다.
- 배정은 일회성 스크립트로 하고, 결과는 JSON에 저장한다.

### 상태 추가

```js
S.level = { current: 'IL', passed: [], history: [] };
// history 항목: { from, to, at, score }
```

### 기존 사용자 이전

`load()` 뒤에 `migrate()`를 실행한다.

1. `S.schema`가 없으면 기존 사용자로 본다.
2. `S.level`을 IL로 만든다.
3. 기존 `S.cards`는 그대로 유지한다.
4. `S.schema = 2`를 저장한다.
5. 백업 파일을 불러올 때도 `migrate()`를 실행한다.

이전 뒤 학습 기록이 하나라도 사라지면 실패다.

### 세션 구성

`buildSession`을 다음 규칙으로 바꾼다.

1. **복습:** 레벨과 관계없이 복습할 차례인 항목을 먼저 넣는다.
2. **새 항목:** 현재 레벨에서 먼저 고른다.
3. **현재 레벨을 다 배웠다면:** 승급 전까지 새 항목을 내지 않고 복습과 승급 심사를 권한다.
4. 사용자가 낮은 레벨을 고른 경우에만 그 레벨의 항목을 낸다.

### 화면

- **홈:** `.plan` 위에 레벨 카드를 둔다. 현재 레벨, 다음 레벨, 진도 막대, 승급 심사 상태를 보여 준다.
- **기록 탭:** 9단계 레벨 경로를 세로로 표시하고 완료, 현재, 잠김을 구분한다. 승급 이력도 표시한다.

## 6. 단어 학습

### 데이터

새 파일 `data/words.json`, 첫 배포 목표는 약 1,200개다.

```json
{
  "id": "w-il-001",
  "opic": "IL",
  "word": "appointment",
  "pos": "noun",
  "ko": "예약, 약속",
  "en": "I have a dentist appointment at three.",
  "enKo": "세 시에 치과 예약이 있어요.",
  "topic": "daily"
}
```

조건:

- `en`에 `word`가 형태 그대로 정확히 한 번 나와야 한다.
- 회화에 쓸모 있는 단어를 고르고, 시험용 단어를 피한다.
- 같은 레벨 안에서 중복을 금지한다. 다의어를 다른 뜻으로 다시 낼 때만 레벨을 달리해 허용한다.

### 복습 단계

기록은 `S.cards`에 함께 저장하고 `SRS.grade`, `SRS.rate`를 그대로 쓴다. `w-` 접두사로 구분한다.

| 횟수 `reps` | 문제 | 방법 |
|---|---|---|
| 0 | `wordIntro`, `wordChoice` | 카드를 본 뒤 한국어 뜻 4지선다 |
| 1~2 | `wordBlank` | 예문 빈칸에 단어 입력 또는 말하기 |
| 3 이상 | `wordRecall` | 한국어 뜻과 예문 해석을 보고 단어 입력 또는 말하기 |

- 오답 보기는 같은 레벨, 같은 품사에서 고른다.
- 단어 소개 카드에서 단어와 예문을 들려준다. 재생 버튼은 `.dock`에 둔다.
- 음성 조작 언어: 소개와 뜻 고르기는 한국어, 빈칸과 회상은 영어. `langOf`가 `curE.stage`를 참고하도록 고치고, 언어 전환 테스트를 추가한다. 뜻 고르기는 "1번", "2번"으로 답한다.

### 학습 흐름

오늘의 학습에 표현과 단어를 함께 넣는다.

| 시간 | 문제 수 | 새 표현 | 새 단어 |
|---|---|---|---|
| 5분 | 12 | 2 | 3 |
| 10분 | 24 | 5 | 5 |
| 20분 | 48 | 8 | 10 |
| 30분 | 72 | 12 | 15 |
| 60분 | 144 | 20 | 30 |

- 순서: 복습 → 새 단어 → 새 표현
- 복습이 제한 수를 넘으면 새 항목을 내지 않는다.
- 학습 탭의 `STUDY_MENU`에 **단어 학습**을 추가해 단어만 공부할 수도 있게 한다.

## 7. 승급 심사

### 응시 조건

현재 레벨에서 아래를 모두 채우면 심사가 열린다.

| 조건 | 기준 |
|---|---|
| 표현 진도 | 해당 레벨의 80% 이상 학습 |
| 단어 진도 | 해당 레벨의 80% 이상 학습 |
| 정착도 | 학습한 항목의 60% 이상이 `reps >= 2` |
| 밀린 복습 | 5개 이하 |

기준값은 `srs.js`의 `PROMOTION` 상수에 모은다. 판정 함수는 순수 함수로 만든다.

```js
SRS.promotionStatus(items, words, cards, level, now)
// → { ready, checks: [{ id, label, value, target, ok }] }
```

홈 레벨 카드에는 조건별 달성 현황을 보여 준다. 조건이 하나라도 부족하면 "복습 3개를 더 하면 열려요"처럼 할 일을 구체적으로 알려 준다.

### 심사 구성

총 25문항, 약 8분, 현재 레벨에서 무작위 출제한다.

| 영역 | 문항 | 형식 |
|---|---|---|
| 단어 | 8 | 뜻 고르기 3, 예문 빈칸 5 |
| 표현 | 7 | 표현 고르기 3, 문장 빈칸 4 |
| 어순 | 5 | 문장 배열 |
| 말하기 | 5 | 한국어 보고 통문장 말하기 |

- 힌트, 다시 듣기, 정답 즉시 표시를 제공하지 않는다.
- 문항별 제한 시간을 둔다. 고르기 20초, 빈칸 30초, 배열 45초, 말하기 40초.
- 마이크를 쓸 수 없으면 말하기를 타이핑으로 대신한다.
- 말하기 채점은 기존 `SRS.gradeSentence`를 쓴다. 관사 같은 작은 단어는 넘어가는 기준을 유지한다.
- 심사 결과는 복습 일정에 영향을 주지 않는다.

### 합격 기준

- 전체 80% 이상, **그리고** 말하기 5문항 중 3문항 이상 정답
- 합격: 다음 레벨로 승급, 축하 화면
- 불합격: 영역별 점수와 틀린 항목을 보여 주고, 틀린 항목을 바로 복습 대상으로 넣는다.
- 재응시: 불합격 후 **12시간 뒤**, 그리고 틀린 항목을 복습한 뒤 가능
- 심사 도중 나가면 나가기 전에 확인을 받는다. 나가면 응시 1회로 치지 않고 재응시 대기도 없다.
- AL은 최고 레벨이다. AL 진도를 끝내면 "최고 레벨 완주"를 표시한다.

### 상태

```js
S.exam = { lastAt: 0, lastLevel: '', attempts: {} };
```

진행 중 앱이 닫히면 해당 심사는 취소한다. 진행 상태를 저장하지 않는다.

### 화면

1. **안내:** 문항 수, 시간, 합격 기준, 응시 시작 버튼
2. **진행:** 기존 `quiz` 화면을 재사용하고 `session.exam = true`로 구분한다. 진행 막대와 남은 시간을 표시한다.
3. **결과:** 점수, 영역별 막대, 합격 여부, 틀린 항목. 합격하면 토타시가 `done` 표정과 `boing` 동작으로 축하한다. 움직임 줄이기 설정을 지킨다.

음성 명령: "승급 심사", "심사 시작", "결과 보기"

## 8. 내 문장 만들기 예시

### 사용자 경험

1. 표현과 뜻이 나온다.
2. 그 아래 **한국어 예시 문장 3개**가 나온다. 예: "나는 매운 음식을 먹고 싶어요."
3. 예시를 누르면 선택 표시만 되고, 사용자는 영어 문장을 직접 말하거나 입력한다. **영어 정답은 미리 보여 주지 않는다.**
4. "다른 예시 보기"로 새 3개를 뽑는다.
5. 선택한 예시가 있으면 AI 교정 요청에 함께 보낸다.

예시 없이 자기 이야기를 써도 된다.

### 데이터

새 파일 `data/examples.json`, 표현 `id`를 키로 쓴다.

```json
{ "day-02": ["나는 매운 음식을 먹고 싶어요.", "오늘은 집에서 쉬고 싶어요."] }
```

조건:

- 표현마다 약 20개, 모두 그 표현으로 영어 문장을 만들 수 있어야 한다.
- 소재를 다양하게 섞고, 쉬운 어휘로 말할 수 있는 내용으로 쓴다.
- 앱 실행 중 AI를 호출하지 않고 파일에서 읽는다. 오프라인에서도 보여야 한다.
- 처음 켤 때 전체를 읽느라 느려지지 않도록, 내 문장 화면을 열 때 처음 불러온다.

### 무작위 선택

```js
S.exampleSeen = { 'day-02': [3, 11, 7] }; // 최근 본 번호
SRS.pickExamples(list, recent, 3)
```

- 최근 본 9개를 제외하고 고른다. 남은 것이 3개보다 적으면 기록을 비우고 다시 고른다.
- 같은 화면의 3개는 서로 달라야 한다.

### AI 교정 변경

`SYSTEM_MAKE`에 선택한 예시를 함께 보낸다. 사용자 문장을 고칠 뿐, 예시를 그대로 번역한 답을 강요하지 않는다. 입력은 계속 "교정할 텍스트"로만 취급한다.

음성 명령: "다른 예시", "예시 바꿔", "1번 예시"는 한국어 화면이어야 동작한다. 내 문장 화면은 영어로 듣는 화면이므로 영어 명령 `other examples`도 추가한다.

## 9. 동기화

### 구성

- **로그인:** Firebase Authentication, Google 로그인
- **저장소:** Cloud Firestore
- **SDK:** 정확한 버전을 `assets/vendor`에 내려받아 함께 배포한다. 처음 로그인과 동기화 외에는 인터넷이 없어도 앱이 정상 동작해야 한다.
- **설정값:** `firebase-config.js`에 둔다. Firebase 웹 설정값은 비밀이 아니며, 보호는 보안 규칙으로 한다.

### 저장 구조

```text
users/{uid}/state/meta   { schema, call, level, exam, settings, days, updatedAt }
users/{uid}/cards/{shard} { items: { [cardId]: card }, updatedAt }
```

문서당 1MiB 제한을 피하도록 카드를 묶음 단위로 나눠 저장한다. 묶음 번호는 `cardId`의 해시로 정한다. 학습 항목 규모를 고려해 16개로 시작한다.

### 보안 규칙

```text
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

### 병합 규칙

병합은 `SRS.mergeState(local, remote)` 순수 함수로 만든다.

| 항목 | 규칙 |
|---|---|
| 카드 | `seen`이 더 최근인 쪽 |
| `S.days` | 합집합 |
| 레벨 | 더 높은 쪽 |
| 승급 이력 | `at` 기준 합집합 |
| 호칭, 설정 | `updatedAt`이 더 최근인 쪽 |
| AI 사용액 | 같은 달이면 큰 쪽 |
| API 키 | 동기화 안 함 |
| 음성 조작 켜짐 | 기기별로 유지 |

충돌을 사용자에게 묻지 않는다. 학습 기록이 사라지는 쪽으로 병합하면 안 된다.

### 동기화 시점

- 앱 열 때, 화면으로 돌아올 때, 학습 종료 때, 답한 뒤 30초 묶음으로 한 번
- 오프라인이면 기기에 저장하고 연결되면 보낸다. 문제 풀이를 막지 않는다.
- 쓰기 횟수를 줄이기 위해 답할 때마다 보내지 않는다.

### 기록 초기화

초기화는 동기화 때문에 되살아나면 안 된다. `S.resetAt`을 두고, 그보다 오래된 원격 기록은 병합에서 제외한다. 로그인 상태면 원격 기록도 지운다. 지우기 전 두 번 확인한다.

### 로그인 화면과 상태

- 설정 탭에 **동기화** 묶음: 로그인 버튼, 계정 이메일, 마지막 동기화 시각, 지금 동기화, 로그아웃
- 로그인은 선택 사항이다. 로그인하지 않아도 지금처럼 쓴다.
- 로그아웃해도 기기의 기록은 지우지 않는다.
- 첫 로그인에서 양쪽에 기록이 있으면 병합 결과를 요약해 보여 준다.

주의: 설치된 PWA에서는 팝업 로그인이 실패할 수 있다. `signInWithPopup`을 먼저 쓰고, 실패하면 `signInWithRedirect`로 대체한다. **실제 안드로이드 기기**에서 설치된 앱과 Chrome 모두 시험한다. 해당 시점의 Firebase 공식 문서로 방법을 다시 확인한다.

### 사용자 안내 절차

Firebase 콘솔 화면이 바뀌었을 수 있으니, 안내하기 전에 공식 문서를 확인한다. 한 번에 한 단계만 안내하고 사용자의 확인을 받는다. 무료 요금제 한도도 그 시점에 확인해 알려 준다.

1. console.firebase.google.com에서 프로젝트 `totasi-english` 만들기
2. 웹 앱 등록, 설정값 복사해 채팅에 전달
3. Authentication → Google 로그인 사용 설정
4. Authentication → 승인된 도메인에 `sglee9649-star.github.io` 추가
5. Firestore 데이터베이스 만들기
6. 위 보안 규칙 붙여 넣고 게시
7. 두 기기에서 로그인해 확인

## 12. 콘텐츠 제작 계획

필요한 콘텐츠:

| 콘텐츠 | 분량 | 예상 크기 |
|---|---|---|
| 신규 표현(NL, NM, NH, AL) | 110개 | 약 30KB |
| 단어와 예문 | 약 1,200개 | 약 250KB |
| 한국어 예시 | 약 8,000개(표현 410 × 20) | 약 500KB |

각 파일은 단계별로 나눠 작성해 품질을 검사한 뒤 합친다. 자동 검사로 문법이나 말투까지 보장할 수는 없으므로, 표본을 사용자에게 보여 주고 어색한 표현을 신고받아 고친다.

**결정 필요:** 예시 8,000개를 만드는 방법

- **권장:** 먼저 표현당 8개로 배포하고, 이후 20개까지 늘린다.
- **대안:** 사용자의 API 키로 일회성 생성 도구를 실행해 한 번에 만든다. 비용은 실행 전 그 시점의 가격으로 계산해 알리고, 결과는 검사 후 저장소에 넣는다.
